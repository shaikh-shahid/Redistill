# Replication Design — Redistill

**Date:** 2026-06-07
**Status:** Approved (design phase)
**Scope:** v1 asynchronous primary→replica replication, custom Redistill↔Redistill protocol (PSYNC-shaped), manual promotion.

## Goals

- Asynchronous primary→replica data replication for read scaling and warm standby.
- Manual promotion primitive (`REPLICAOF NO ONE`) usable by an operator or a future automated controller.
- Maximum reuse of existing machinery: the `aof_log` write hook, RESP framing (`aof.rs`), the bincode snapshot (`persistence.rs`), the replay path through `execute_command`, and `MaybeStream` (TLS).
- A protocol shape that allows partial resync and full Redis wire-compatibility to be added later without a redesign.

## Non-Goals (explicitly deferred)

- **Automatic failover** (Sentinel-style quorum / leader election). v1 ships only the manual promotion primitive that such a layer would drive.
- **Redis Cluster membership** (16384 hash slots, gossip "cluster bus", `MOVED`/`ASK`). Entirely separate, much larger project.
- **Full Redis wire-compatibility** (real Redis RDB wire format, PSYNC `CONTINUE`). Blocked on the core data types (lists/sets/zsets/streams) existing first; revisit afterward.
- **Partial resync / replication backlog.** Protocol carries replid+offset so this can be added later; v1 always full-syncs on (re)connect.
- **Semi-synchronous replication / `WAIT`.** v1 is async-only.

## Decisions (settled during brainstorming)

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Wire protocol | Custom Redistill↔Redistill, **PSYNC-shaped** | Real-Redis interop is fragile until all data types exist (type gap). Custom reuses persistence/AOF directly. Shape mirrors PSYNC for a clean upgrade path. |
| Failover | Manual replication only | Failover is a separate layer built *on top of* replication; manual replication is the mandatory prerequisite and ships useful HA/read-scaling now. |
| Reconnect resync | Full resync only | Simplest correct option. Protocol retains offset for future partial resync. |
| Consistency model | Async only (no `WAIT`) | Redis default. Documented trade-off: last unacked writes can be lost on failover. |
| Read-only replica | Enforced | Matches Redis. Replication stream bypasses the check via the internal replay path. |

## Architecture

### Roles

A node holds a global `ReplState` and is in one of two states:

- **Primary** (default) — accepts client writes; tracks connected replicas; fans out every write.
- **Replica** — connects to a primary; receives snapshot + live command stream; applies them; rejects client writes (read-only).

### Propagation tap

`aof_log(command)` is already called after every successful write (main.rs:210, 234, 267, …). Add a sibling `repl_feed(command)` at the same sites, ideally folding both behind one `on_write(command)` helper. On a primary, `repl_feed`:

1. Increments the **master replication offset** by the serialized byte length.
2. Pushes the RESP frame into a `tokio::sync::broadcast` channel.

```
   client writes ──> execute_command ──> store mutate
                            │
                            ├──> aof_log(command)        [existing]
                            └──> repl_feed(command)      [new]
                                     │  offset += len
                                     ▼
                            broadcast::Sender<Bytes>
                              │         │         │
                          replica-1  replica-2  replica-3   (per-socket tasks)
```

### Per-replica fan-out

When a replica attaches, the primary spawns a task owning that socket that consumes the broadcast channel and writes frames to the replica. Reuses `MaybeStream` (TLS free) and the `JoinSet`-based connection model.

**Why broadcast over per-replica queues:** one cheap clone per write, no central lock; a slow replica that overflows its lag buffer is dropped (forcing reconnect → full resync) rather than stalling the primary's write path.

## Handshake & full sync

### Triggering

- `REPLICAOF <host> <port>` command at runtime.
- `[replication] replicaof = "host:port"` config option at startup.

### Handshake (PSYNC-shaped, Redistill-native)

```
replica ──> primary   PING
replica <── primary   +PONG
replica ──> primary   REPLCONF listening-port <p>
replica ──> primary   AUTH <pass>               (if primary has a password)
replica ──> primary   PSYNC ? -1
replica <── primary   +FULLRESYNC <replid> <offset>
primary ──> replica   <snapshot payload>        (length-prefixed bincode dump)
primary ──> replica   <live RESP command stream…>
```

`<replid>` is a random hex run-id generated by the primary at boot. The replica persists `replid` + `offset` so the protocol is partial-resync-ready, though v1 always full-syncs.

### The consistency cut (critical correctness point)

The snapshot and the live stream must join at exactly one point — no gap, no duplication. `INCRBY`/`HDEL` are **not** idempotent, so double-apply corrupts data; a gap loses writes. Reuse the existing stop-the-world pattern from `aof.rewrite()`:

1. Subscribe the new replica to the broadcast channel **first** (buffering live writes).
2. Under a brief barrier, capture the **current offset** as the snapshot cut point and take a point-in-time bincode snapshot.
3. Send `+FULLRESYNC <replid> <cut_offset>`, then the snapshot bytes.
4. Release the buffered stream, **discarding any buffered frame with offset ≤ cut_offset** (already in the snapshot); forward the rest.

Guarantees exactly-once: every write is in the snapshot *or* the stream, never both, never neither.

### Replica apply path

On snapshot receipt: `store.clear()`, load the bincode dump (reuse `persistence.rs` load), then feed each streamed RESP frame into `execute_command` with an authenticated scratch `ConnectionState` — the same path AOF replay uses (main.rs:1535). Replica advances its local offset per applied frame.

## Promotion & read-only enforcement

### Read-only enforcement

In replica state, client write commands are rejected with:
```
-READONLY You can't write against a read only replica.
```
Reads are served normally. The replication stream **bypasses** this check (it applies via the internal replay path, not the client command path). Reuses the existing write-vs-read classification (the set of commands that call `aof_log`).

### Promotion — `REPLICAOF NO ONE`

1. Stop the replica-side stream task; disconnect from the old primary.
2. Flip `ReplState` → Primary; generate a fresh `replid`; keep current offset.
3. Resume accepting client writes.

Data is already in memory (applied live), so promotion is near-instant — no reload. This is the primitive a future Sentinel/k8s controller drives.

## Auth & TLS

Reuse existing facilities. If the primary has a password, the replica authenticates using a `[replication] masterauth` config value. Replication links ride `MaybeStream`, so TLS works with no new code.

## Observability

Fills a current gap (INFO has no replication section today).

- **`INFO replication` section:**
  - Primary: `role:master`, `connected_slaves`, per-replica `ip/port/offset`, `master_replid`, `master_repl_offset`.
  - Replica: `role:slave`, `master_host`, `master_port`, `master_link_status` (up/down), `slave_read_only`, replication offset.
- **New Prometheus metrics:** `redistill_connected_replicas`, `redistill_master_repl_offset`, `redistill_replica_link_up`.

## Failure handling & edge cases

- Replica loses primary link → reconnect with backoff → full resync.
- Slow replica overflows broadcast lag buffer → dropped → reconnect → full resync.
- `REPLICAOF` to a new primary while already a replica → tear down old link, full resync from new.
- Refuse `REPLICAOF` to own address (self/cycle guard).
- Snapshot send failure → drop that replica; it retries.

## Configuration surface

New `[replication]` config section:

| Key | Type | Default | Meaning |
|-----|------|---------|---------|
| `replicaof` | string (`"host:port"`) | unset | Start as a replica of this primary. |
| `masterauth` | string | unset | Password used when authenticating to the primary. |
| `replica_read_only` | bool | `true` | Reject client writes while a replica. |
| `repl_backlog_size` | int (bytes) | 1048576 (1 MiB) | Broadcast lag-buffer capacity before a slow replica is dropped. |

Env-var overrides for each, consistent with existing config conventions.

## Testing

Integration tests use two real Redistill instances on different ports:

- Full-sync correctness (replica matches primary after attach).
- Live propagation (writes on primary appear on replica).
- Read-only rejection on replica.
- Promotion (`REPLICAOF NO ONE` → replica accepts writes).
- Reconnect → full resync after a dropped link.
- **Mid-stream non-idempotent commands** (`INCRBY` during full sync) to prove the consistency cut applies exactly once.

Unit tests: offset accounting, write-vs-read classification, self-replication guard, `replid` generation.
